## 1. Экран отзывов (и длинные тексты)

**Сейчас.** `ReviewCard` (профиль/список/деталь) режет текст по `maxTextLines`: профиль и 09b — 3 строки, 09d — без
ограничения, но это та же карточка с рамкой внутри прокрутки + `InfoCard` «Проект завершён…». Намёка «читать полностью»
у обрезанного текста нет. 09b целиком грузит все отзывы (`UserReviews(summary, items)`).

**Дизайн (Figma).**
- 09d становится полноценным экраном «Отзыв», не карточкой: заголовок отзыва крупно, оценка звёздами, строка
  «Проект · завершён в мес. год», блок автора (Card/Person: аватар, имя, роль, иконка чата), текст без рамки
  (`bodyLarge`, свободный межстрочный интервал), прокрутка. Текст не урезается.
- Карточка отзыва в списке и превью: строка автора кликабельна, справа иконка чата; текст 3 строки и «Читать
  полностью», если он обрезан.
- 09b: шапка-сводка (средняя оценка крупно, «N отзывов · M положительных»), список, футер подгрузки («Загрузка…» /
  «Повторить»), пустое состояние и ошибка.

**Код.**
- `ReviewCard`: строка автора на базе `PersonSummary`, `onAuthorClick`, `onChatClick`; «Читать полностью» по
  `TextLayoutResult.hasVisualOverflow`. Чат не показывается, если автор — зритель.
- `UserReviewsScreen`/`UserReviewsViewModel`: `LazyColumn` с догрузкой на последних элементах, состояния
  `isLoadingMore`/`loadMoreFailed`, повторный запрос не запускается, пока идёт предыдущий.
- `ReviewDetailsScreen` переработать под новый макет.
- Домен: `getReviews(id)` → страница `ReviewsPage(items, hasMore)`; сводка (`average`, `count`, `positiveCount`) берётся
  из профиля; `getReview(id)` → `getReview(userId, reviewId)`, маршрут `profile/{userId}/reviews/{reviewId}`.

**Сеть.**
- `GET /users/{id}/reviews?limit&offset` (limit ≤ 100). В ответе **только `items`, без `total`**: «есть ещё» =
  `items.size == limit`; число отзывов и рейтинг — из `GET /users/{id}/profile` (`review_count`, `rating`,
  `positive_review_count`).
- Отзыва по id в API нет: деталь берётся из кэша страниц репозитория; промах (восстановление после смерти процесса)
  — догрузка страниц этого пользователя до нахождения (с потолком), иначе «Отзыв не найден».
- Длина `text` в спецификации не ограничена; клиент ничего не режет в данных, только в отображении. Вопрос бэкенду: есть
  ли лимит.
- Автор: `author_user_id`, `author_display_name`; признака верификации в отзыве нет, щит у автора не показываем.
  `author_role` — свободная строка (значения не описаны).

## 2. Авторизация в Figma

**Сейчас.** `SignInScreen` и `VerifyEmailScreen` собраны из компонентов дизайн-системы, в Figma экранов входа нет
(`sprint-1.md`, «Регистрация по домену email»). Реальный API требует другого потока, поэтому рисуем поток бэкенда.

**Что рисуем** (страница «MatchLab App», нумерация продолжается после 18; «Документация» обновляем):
- 19 «Регистрация»: почта вуза, пароль (8–72 байта в UTF-8, с иконкой «показать»), «Зарегистрироваться», «Уже есть
  аккаунт? Войти», строка-гарантия `SecurityNote`.
- 19b «Подтвердите почту»: «Мы отправили письмо на …», поле «Ссылка или код из письма», «Подтвердить», «Отправить письмо
  ещё раз» (с обратным отсчётом), «Я уже подтвердил(а)».
- 20 «Вход»: почта, пароль, «Войти», «Создать аккаунт».
- Состояния: загрузка кнопки; домен вуза не подключён (403); почта занята (409); ссылка просрочена или уже использована
  (410/404); неверная почта или пароль (401); почта не подтверждена (403); нет сети / сервис недоступен (503).
- Заставка при восстановлении сессии.
- Новый компонент `Input/Password` (иконка глаза) в Design System.

**Сеть.** `POST /auth/register` (201 `pending`, 403, 409, 503), `POST /auth/email/confirm` (204, 403, 404, 409, 410),
`POST /auth/login` (200 `user_id` + `access_token`, 401, 403). Повторный `register` с той же почтой — это «отправить
ещё раз» (заменяет пароль и токен). Пароль живёт в памяти ViewModel только на время потока: не в `SavedState`, не в
логах. Токен из письма принимается как вставленная ссылка (разбор `token=`) или строка целиком; deep link — позже.
401 на `/auth/login` — неверный пароль, а не выход. Код — по Части C архитектора.

## 3. Настройки: только «Открыт к сотрудничеству»

**Сейчас.** Экран 18: два тумблера приватности (`PrivacyOption.ParticipatedProjects`, `Contacts`) и «Выйти из аккаунта».

**Станет.** Один тумблер «Открыт к сотрудничеству» с пояснением; «Выйти из аккаунта» остаётся (допущение: это действие, а
не настройка). Тумблеры приватности и их domain/data/mock/тесты удаляются; `GET/PUT /users/me/settings` остаются в
`:gateway`, не используются.

**Сеть.** `open_to_collaboration` — поле **профиля**, не настроек. `PUT /users/me/profile` заменяет **все** поля
(`display_name` обязателен), поэтому переключение — это `GET /users/me/profile` + `PUT` с изменённым флагом, одной функцией
в `:gateway` (`updateMyProfile { copy(...) }`), чтобы не затереть остальное. Оптимистичное переключение с откатом уже
есть. Гонка с редактированием профиля (у профиля нет `revision`) принимается и описывается. После изменения кэш
профиля обновляется (`observeMyProfile`). Фича `settings` не зависит от `profile`, общий вызов лежит в `:gateway`.

**Последствие.** Рекомендации людей и фильтр `open_only` показывают только «открытых»: пока никто не включил флаг, блок
«Люди для ваших проектов» на ленте может быть пустым; значение по умолчанию задаёт сервер.

**Тесты.** ViewModel (переключение, откат, повтор), data (read-modify-write сохраняет остальные поля).

## 5. Переключатель «Проекты | Люди»

**Сейчас.** `AppSegmentedControl`: у каждого сегмента своя заливка, цвет меняется анимированно, пилюля не двигается.

**Станет.** Одна белая пилюля под подписями, плавно (≈250 мс, `FastOutSlowInEasing`) уезжает на выбранный сегмент, цвет
подписи переливается. Реализация: пилюля с `offset` от `animateFloatAsState(selectedIndex)`, ширина `(ширина − отступы)/n`,
работает для любого числа сегментов и RTL; роли доступности как сейчас; быстрые тапы не ломают анимацию.
Геометрия пилюли — чистая функция с тестом; новая запись в `:catalog` (2 и 3 сегмента).

**Figma.** Вариант выбранного сегмента слева/справа + описание движения (Smart animate, 250 мс, ease in-out).

**Сеть.** Нет. Но при переключении на «Люди» рекомендации грузятся при первом показе и кэшируются на время жизни экрана,
а не на каждый тап.

## Баги

### Баг 1. Многократные нажатия открывают несколько экранов

**Причины (проверено).**
1. `AppNavHost` вызывает `navigate(...)` (22 места) и `popBackStack()` (17) прямо из обработчиков: ни защиты, ни
   `launchSingleTop`, ни своих переходов нет.
2. Пока идёт анимация перехода, прежний экран остаётся в композиции и кликабелен. `LoadingState` и `MessageState` не
   перехватывают касания (просто `Box`/`Column` без pointer input), поэтому тапы проваливаются на кнопку старого экрана.
   Экраны, у которых с первого кадра прокручиваемое содержимое (управление проектом), касания поглощают — отсюда «у
   карточки во вкладке „Я инициатор“ бага нет».
3. `openChatWith` запускает корутину на каждый тап: N тапов — N экранов чата.
4. Компоненты не ограничивают повторные нажатия; двойной тап по стрелке «назад» закрывает два экрана.

**Исправление (слоями).**
a. Навигация (`:shared`): `navigateOnce(from, …)`, `navigateSingleTop(from, …)` и `popBackStackOnce(from)` принимают запись
   экрана, который просит перейти, и выполняются, только пока эта запись на вершине стека (`currentBackStackEntry?.id ==
   from.id`); все 39 вызовов заменены. Условие «верхняя запись `RESUMED`» не годится: обе записи перехода остаются ниже
   `RESUMED` до конца анимации, и события формы терялись без повтора (проверено на эмуляторе). `launchSingleTop = true` —
   для маршрутов без аргументов (настройки, редактирование профиля, формы), но не для профиля/проекта (профиль →
   профиль должен стековаться). `openChatWith` — `ExclusiveLauncher` на время запроса, экран открывается, только если
   пользователь всё ещё на экране, где был тап.
b. Состояния: `LoadingState` и `MessageState` (и экраны-оверлеи) поглощают касания, чтобы они не доходили до экрана под
   ними.
c. Компоненты (`:components`): `Modifier.onceClickable`/`rememberDebouncedClick` (окно ≈600 мс на монотонных часах) в
   `AppCard(onClick)`, `AppButton`, `AppIconButton`, `CardIconButton`, строках списков, действии `SectionHeader`, стрелке
   `AppTopBar`. Не применять к переключателям, выбору, чипам.
d. ViewModel (особенно важно с сетью): аудит всех действий, меняющих данные, — `isSubmitting`-страж в создании проекта,
   добавлении роли, публикации/снятии, добавлении/правке работ и документов, сохранении профиля, настройках, регистрации
   и повторной отправке письма (кулдаун), открытии чата. В API нет ключей идемпотентности: повторный `POST /projects`
   создаёт второй проект, повторный `POST /complaints` — вторую жалобу.

**Проверка.** Модульные тесты на дебаунс (фейковые часы) и условие навигации; на эмуляторе `emulator-5554` сценарий
«5 тапов подряд за ~100 мс» по: «Все N» отзывов, карточке проекта в поиске, кнопке чата, стрелке «назад», карточке во
вкладке «Я инициатор»; ожидание: ровно один новый экран в стеке (проверка `uiautomator dump`), «назад» возвращает на
исходный экран за один раз.

### Баг 2. Нет редактирования портфолио и «Образования и документов»

**Сейчас.** На 10 и 10b карточки работ и документов не редактируются: тап по работе открывает её ссылку, по документу
ничего; удаления и правки в `sprint-1.md` помечены как «нет».

**Станет.** Тап по карточке работы или документа в **своём** профиле (10 и 10b) открывает редактор: формы 11 и документа в
режиме правки с заполненными полями. Действия: «Сохранить», «Отправить на проверку» (если не подтверждено), «Удалить» (с
подтверждением), «Открыть ссылку». В чужом профиле тап по работе по-прежнему открывает ссылку. После правки статус
сбрасывается (серверное правило) — об этом предупреждение в форме; для отклонённых показывается `moderation_comment`.

**Сеть.** `GET /users/me/achievements?kind=` (education | certificate | scientific | project; list без `total`),
`POST` (создаёт неподтверждённое), `PUT /…/{id}` (сбрасывает подтверждение, нужен `expected_revision`), `POST /…/{id}/submit`,
`DELETE /…/{id}` (204, «с сохранением истории»). 409 — запись изменилась: перезагрузить и сообщить. Вместо файла
отправляется ссылка в `url`; `evidence_file_id` (загрузка файлов) вне объёма. Значения `status` в спецификации не описаны.

**Figma.** Новые кадры «11b Редактировать работу» и «11c Редактировать документ» (нижняя панель «Сохранить» + текстовая
«Удалить», диалог подтверждения, баннер статуса), признак «можно открыть» на карточках 10/10b.

**Тесты.** Валидация черновиков (уже есть), ViewModel (правка, удаление, 409, защита от двойного нажатия), data
(маппинг, `revision`).

### Баг 3. Карточка инициатора

**Причина (проверено).** `PersonSummary` (`:components/PersonCard.kt`) при `showChatButton` выравнивает строку по
`Alignment.Bottom`: аватар 48 dp прижимается к низу трёхстрочной колонки (имя, подпись, статистика).

**Исправление.** Аватар по центру по вертикали и крупнее (64 dp, как в шапке профиля), кнопка чата тоже по центру,
текстовая колонка тянется. Меняется всё, что строится на `PersonSummary`/`PersonCard`. В Figma — компонент «Card/Person»
(аватар 64, центрирование) и проверка кадров, где он используется (04 и др.). Проверка — сравнение скриншотов на
эмуляторе и запись в `:catalog`.

## Общее про сеть для всех пунктов

- Каждый экран с данными: загрузка (индикатор с задержкой ≈150–200 мс, чтобы не мигал), ошибка с «Повторить», пусто,
  «не найдено/нет доступа». Ошибки сети не теряются молча.
- 401 на авторизованный запрос → перепроверка токена (`GET /sessions/current`), выход из сессии только при подтверждённом отказе (кроме
  `/auth/login`). 409 → перезагрузка и понятное сообщение.
- Пагинация (`limit` ≤ 100, `offset`) во всех списках, где их много; «Найдено N» — из `total`, где он есть.
- Профили людей в карточках проектов запрашиваются отдельно (в `Project` только `owner_user_id`): кэш и объединение
  одинаковых запросов, иначе список из 20 проектов — 20 запросов.
- Значения строковых полей, не описанные в спецификации (тип/статус проекта, действие перехода, статус достижения,
  `study_level` и др.), не угадываются (правило «без догадок», `docs/api-gaps.md`): поле читается как «неизвестно» (свободный текст вроде
  `study_level` показывается как пришёл), действие, которому нужно значение, выключено флагом. Единственная пометка `@UnverifiedContract` —
  разбор вставленной ссылки из письма (G01).

## Вопросы и допущения

Допущения по умолчанию (поправьте, если не так):
- «Экран отзывов» — переработка 09d (деталь) и 09b (список); 09b/09d уже есть, но деталь — это карточка.
- В настройках остаётся «Выйти из аккаунта»; чип «Открыт к сотрудничеству» на экране 09 не добавляется.
- Токен из письма вставляется пользователем (ссылка или код); deep link — отдельным шагом.
- Загрузка файлов и показ аватаров по `avatar_file_id` вне объёма (нужны выбор файла и загрузка картинок).

Нужно от пользователя:
- Авторизация Figma MCP.
- Значения строковых полей API (тип и статус проекта, действие перехода, `duration`, `mine`, статусы откликов и
  достижений, `study_level`, формат дат) или примеры реальных ответов.
- Решение по подтверждению документов: без загрузки файлов ссылка уходит в публичное поле `url` и видна всем, кто
  открывает профиль. Предлагаю оставить ссылку с предупреждением в форме, а загрузку файлов через Media сделать отдельным
  блоком.
- Способ запустить реальный сервер для проверки (локальный Docker Compose бэкенда с Mailpit или другая сеть): с машины
  разработки `api.matchlab.space` недоступен.
