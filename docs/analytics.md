# Аналитика: Яндекс AppMetrica (план)

Статус на 2026-10-21: **решения заказчика получены (§7), реализация идёт по контракту `docs/contract-analytics.md`.** Задачи — `docs/sprint-2.md`, T15–T22.

## 1. Что берём и что хотим мерить

«Яндекс Метрика» для мобильных приложений называется **AppMetrica** (SDK для Android и iOS). Обычная Метрика с JS-счётчиком нужна
сайтам; у нас сайт — одна страница подтверждения почты (`docs/backend-deeplinks.md`), её аналитика в этот план не входит.

Что хотим отслеживать (слова заказчика): клики на карточки проектов, клики на пользователей, клики на проект.

| Событие | Когда | Параметры |
|---|---|---|
| `project_card_click` | нажатие на карточку проекта в любом списке | `project_id`, `source` |
| `user_click` | нажатие на человека (карточка, строка списка, имя автора) | `user_id`, `source` |
| `project_click` | по нажатию открылась страница проекта (решение заказчика: «клик на проект» — открытие страницы проекта) | `project_id`, `source` |

`source` — откуда нажали, фиксированный список значений (§3).

## 2. Как это устроено в AppMetrica (по документации Яндекса)

Проверено по официальной документации на 2026-10-20; версии перед внедрением сверить заново.

- **Android.** Зависимость `io.appmetrica.analytics:analytics` (в документации 8.6.0). Инициализация в `Application.onCreate`:
  `AppMetrica.activate(this, AppMetricaConfig.newConfigBuilder(API_KEY).build())`. Событие:
  `AppMetrica.reportEvent(name, Map<String, Any>)` (есть вариант с JSON-строкой). Ключ приложения — «Настройки → Основные» в
  консоли AppMetrica. Журнал SDK включается `withLogs()` в конфигурации. Геолокация по умолчанию выключена; рекламные
  идентификаторы выключаются `withAdvIdentifiersTracking(false)`. Отправку можно выключить `withDataSendingEnabled(false)` и
  включить позже `AppMetrica.setDataSendingEnabled(true)` (например, после согласия). Профиль привязывается к пользователю
  через `AppMetrica.setUserProfileID(id)`; без него профиль создаётся по `appmetrica_device_id`.
- **iOS.** SDK 7.0.0 (по документации): CocoaPods `AppMetricaCore` или SPM `https://github.com/appmetrica/appmetrica-sdk-ios`
  (выбирать только нужные модули). Модуль `AppMetricaAdSupport` (собирает в том числе IDFA, рекламный идентификатор) **не
  подключаем**: он нам не нужен, а доступ к IDFA на iOS требует согласия пользователя (App Tracking Transparency) и отдельного
  заявления в App Store. Инициализация в `application(_:didFinishLaunchingWithOptions:)`:
  `AppMetrica.activate(with: AppMetricaConfiguration(apiKey: …)!)`; событие: `AppMetrica.reportEvent(name:parameters:onFailure:)`.
- **Kotlin Multiplatform.** Официальной обёртки для KMP нет. Поэтому SDK подключается в платформенных приложениях, а общий код
  знает только свой маленький интерфейс (§3).
- **Задержка.** События отправляются пачками; в консоли они появляются не сразу (документация советует подождать около 10 минут).
- **Размеры.** Ограничений на длину имени события и значений документация явно не называет; держим имена короткими, значения —
  идентификаторы и фиксированные слова.

## 3. Архитектура

Правила проекта: фича не зависит от другой фичи и ничего не знает о навигации; наружу — только колбэки. Все колбэки нажатий уже
собраны в одном месте — `AppNavHost` (`:shared`), и там известно, откуда нажали. Поэтому события шлёт **навигационный слой**, а
не фичи:

1. **Новый модуль `:analytics`** (только `commonMain`, без SDK): интерфейс
   `Analytics { fun track(event: String, params: Map<String, String> = emptyMap()) }`, пустая реализация `NoOpAnalytics`,
   каталог событий (имена и значения `source` в одном месте), функции сборки событий (`projectCardClick(id, source)`,
   `userClick(id, source)`) — чистые, с тестами.
2. **Платформа даёт реализацию параметром `App(…, analytics)`**, как уже даёт `SecureStore`: Android — класс в `:androidApp` над
   AppMetrica SDK, iOS — Swift-класс в `iosApp/`, который реализует протокол `Analytics` и зовёт `AppMetrica.reportEvent`.
   Строковые параметры (`Map<String, String>`) переходят в Swift без потерь. SDK не попадает ни в `:shared`, ни в фичи, а
   компиляция iOS-части общего кода не зависит от SDK.
3. **Граф DI.** `AppComponent` получает `Analytics`; `SessionComponent`/`AppNavHost` берёт его оттуда. Без ключа (пустой) —
   `NoOpAnalytics`: сборки и тесты не требуют ключа и не засоряют статистику.
4. **Точка отправки.** `navController.navigateOnce(entry, route)` возвращает `true`, только если переход выполнен. Событие
   отправляется по этому результату, поэтому очередь нажатий (двойной тап) считается один раз.
5. **Сбои аналитики не ломают приложение:** платформенная реализация ловит исключения SDK; `track` не бросает.

## 4. Что уходит в аналитику (и что нет)

- Уходят: фиксированное имя события, `source` из списка, **идентификатор** проекта или пользователя (UUID сервера).
- Не уходят: имена, почта, тексты сообщений и отзывов, названия проектов, ссылки, любые вводимые пользователем строки.
- `appmetrica_device_id` SDK создаёт сам. Идентификатор аккаунта передаём как `setUserProfileID` (решение заказчика 2026-10-21):
  он связывает события с конкретным человеком на всех его устройствах; при выходе из аккаунта профиль снимается. Это нужно
  отразить в политике конфиденциальности.
- Рекламные идентификаторы и геолокация выключены.
- Нужно отразить сбор в политике конфиденциальности и в формах магазинов (Google Play «Безопасность данных», App Store
  «Конфиденциальность приложения»). Яндекс — российская компания; подходит ли это под требования о локализации персональных
  данных граждан России, в этом плане не оценено: это решает тот, кто отвечает за политику и юридическую часть.
- Согласие/отказ (решение заказчика): переключатель «Статистика использования» в настройках и чекбокс «Отправлять статистику
  использования» при регистрации, по умолчанию включён; он задаёт начальное значение настройки. До выбора отправка выключена
  (`withDataSendingEnabled(false)`); вход в аккаунт на устройстве без выбора записывает значение по умолчанию (включено).
  В макетах регистрации (20) и настроек (18) этих элементов нет: допущение и задание дизайнеру.

## 5. Конфигурация и окружения

- Ключ приложения не коммитится. Передаётся Gradle-свойством (по образцу адреса сервера): `-Pmatchlab.appmetricaKey=<ключ>` или
  строкой в `local.properties`; пустой ключ — аналитика выключена (`NoOpAnalytics`).
- Решение заказчика: одно приложение в AppMetrica. Чтобы отладочные нажатия не попадали в боевую статистику, отладочные сборки
  собираются без ключа (аналитика выключена) или с ключом по желанию разработчика.
- Отладочные сборки Android включают журнал SDK (`withLogs()`).
- Релиз Android: сейчас `isMinifyEnabled = false`; если минификацию включат, правила для AppMetrica поставляются с библиотекой,
  но проверить сборку.

## 6. Проверка

Эмулятор и устройство агентами не используются (запрет пользователя), поэтому:

- **Автоматически:** тесты на чистые функции событий (имена, параметры, пустой идентификатор не отправляется), на «одно
  нажатие — одно событие» через запись вызовов (`RecordingAnalytics`), на граф DI (аналитика есть, без ключа — пустая).
  Сборка `:androidApp:assembleDebug`, компиляция iOS-части общего кода.
- **Вручную (за пользователем):** собрать отладочную сборку с ключом, нажать карточку проекта и человека, дождаться событий в
  консоли AppMetrica («События» / «Отчёты → События»), сверить имена и `source`. Для iOS — после подключения Swift-части.

## 7. Решения заказчика (2026-10-21)

1. **«Клик на проект»** — открытие страницы проекта (`project_click`); «клик на карточку проекта» (`project_card_click`) — нажатие на
   карточку в списке. Нажатие на карточку даёт оба события.
2. **Идентификатор пользователя** передаём (`setUserProfileID`).
3. **Согласие:** переключатель в настройках **и** чекбокс при регистрации (по умолчанию включён, задаёт начальное значение настройки).
4. **Одно приложение** в AppMetrica. Ключ приложения нужен от заказчика (передаётся как `-Pmatchlab.appmetricaKey`); пока его нет, аналитика
   выключена.
Открыто: другие события (отклик на роль, создание проекта, регистрация) заказчик не запрашивал, в этот объём они не входят.
