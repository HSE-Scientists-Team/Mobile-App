## Хвосты спринта 1

Невыполненные или выполненные с ограничением стори прошлого спринта (подробнее — `docs/sprint-1.md`, «Известные ограничения»):

- «видеть статус проверки» и «получать уведомление о результате проверки» — выключены флагом `verificationStatuses` (G12), уведомлений в API нет (G61);
- «загрузить профильные сертификаты» и «продемонстрировать несколько документов об образовании» — только ссылкой, файлов нет (G17, G18);
- «общаться с кандидатом в чате», «связаться с инициаторами проекта», «закрытость переписки» — чат локальный, API нет (G50);
- «получать рекомендации людей на роль в проекте» — на ленте случайные люди, не на роль (G32);
- «искать людей в проект на роль по фильтрам» — роль на сервер не уходит (G31); вход с роли идёт через 07b, достижим после включения создания проектов;
- «опубликовать новый проект», «снять с публикации», «просматривать свои проекты» — включены `docs/api-values.md`, на сервере не проверены;
- «указать сроки проекта» — на доске теперь в строке «1 Спринт» (в `sprint-1.md` значилась как 2-го); сделано, ISO-даты включены.

## Блоки: состав и решения

Ручки: все пути под `/api/v1`, защита — `bearerAuth`, ответы ошибок общие: 400 некорректные поля, 401 сеанс, 403 права или блокировка,
404 не найдено, 409 конфликт версии, состояния или занятое место, 500, 503, 504. Чтение — `failureText` и «Повторить» как в спринте 1.

### Блок 0. Служебный: отклики, участники, жизненный цикл (не стикер)

- `:common`: `ProjectJoin` (`JoinId`, `projectId`, `roleId`, кандидат `UserId`, `message`, время создания, `type` и `status` — `null`, пока
  таблицы значений нет; сырые строки в модели не живут), `ProjectMember` (человек, `roleId`, название роли), в `Project` — `members`,
  `pendingJoinCount`, `viewerIsMember` (id пользователя сессии есть среди `members`).
- `:gateway`: DTO `ProjectJoinDto` / `ProjectJoinListDto` / `ProjectJoinInputDto` / `ProjectJoinDecisionDto`, `ProjectDto` +
  `members`, `pending_join_count`, `completed_at_unix`, `moderation_hidden`, роль + `description` (читается и возвращается как пришло:
  PUT заменяет); `ProjectJoinsApi` (apply, invite, listForProject, listMine, decide, withdraw); `ProjectsApi` + `update`, `updateRole`,
  `deleteRole`, `removeMember`, `leave`; `ComplaintsApi.create`; `ProjectActions` + `START = "start"`, `COMPLETE = "complete"`, `CANCEL = "cancel"`
  (`@UnverifiedContract`, значения в `api-values.md`, §2).
- `:feature:responses:{domain,data}` создаются (сейчас только `ui` с `ApplicationCard`); `:feature:complaints:{domain,data,ui}` — в блоке 5.
- Тесты: клиент `:gateway` на `ktor-client-mock`; domain и маппинг — `tester`.

## Решения при реализации блоков 5–8 (2026-10-19)

- Списки откликов читаются целиком в кэш сессии (страницы по 100, не больше 10); чтение списка проекта (07d) с профилями кандидатов держит общий замок, действия на это время ждут.
