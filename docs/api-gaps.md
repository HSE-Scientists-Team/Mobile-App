# Реестр пробелов API (правило «без догадок»)

Статус на 2026-10-18. Источник правды о бэкенде — `docs/openapi.yaml` (Gateway API **v2.5.0**; относительно v2.4.0 добавлен только административный API `/api/v1/admin/*` для сотрудников — модерация, аудит, пользователи, проекты; клиентскому приложению он не нужен. Все 43 публичных пути и все схемы клиента побайтно те же, поэтому пробелы ниже остались прежними). **Требование пользователя: API не угадывать.**
Работаем только по тому, что в спецификации определено; всё, чего не хватает, помечается здесь и в коде, и приложение к этим местам
вернётся, когда бэкенд опишет API. Этот файл главнее документов архитекторов (`docs/gateway-block2-profiles.md`,
`docs/gateway-blocks3-5-search-and-projects.md`): везде, где они предлагают «лучшее предположение» (синонимы, значения enum, форматы дат,
значения `mine`/`action`/`type`), действует это правило, а не предложение.

## Правило

1. **Определено = можно использовать.** Определено то, что названо в схеме или описании: пути и методы, имена и типы полей, обязательные
   поля, границы (`limit` 1..100, `offset` 0..10000), enum параметра `kind` у достижений (`education | certificate | scientific | project`),
   `RegistrationResult.status = pending`, `EmailStatus.status = pending | verified`, коды ответов из таблицы ответов, смысл из `summary`/`description`
   (например, «Создать и сразу опубликовать проект», «Повтор с тем же email заменяет пароль и токен заявки»).
2. **Строка без перечня значений (`type: string` без `enum` и без описания значений) — пробел.** Мы НЕ придумываем её значения: ни в запросах,
   ни при разборе ответов (никаких синонимов, регистров, «наиболее вероятных» строк). Что делаем вместо этого:
   - **запрос:** параметр или поле с неопределёнными значениями не отправляем; если поле обязательно на сервере, а значения не известны, то
     операция в режиме Gateway **недоступна** (возможность выключена флагом, см. ниже), а не отправляется «на удачу»;
   - **ответ:** неопределённая строка читается как «неизвестно» (`null`) либо показывается как есть, если это свободный текст; интерфейс
     скрывает то, что без неё не построить (чип, баннер, действие);
   - **сохранение чужих данных:** при «прочитал — изменил — записал» (`PUT /users/me/profile`) значения неопределённых полей возвращаются на
     сервер как пришли.
3. **Возможности (capabilities).** Каждый источник данных, у которого есть пробел, объявляет флаги возможностей (например,
   `ProjectsCapabilities.canCreate`). В режиме `Backend.Gateway` флаг выключен, пока пробел не закрыт; в режиме `Backend.Mock` включён (мок играет
   более полный сервер, чем есть). Интерфейс читает флаги и прячет или отключает затронутое действие с понятным текстом, а не показывает вымышленные
   данные. Закрытие пробела = смена значения флага + реализация вызова, больше ничего.
4. **Пометки.** Каждое место в коде, где пробел сказывается, помечено комментарием `API-GAP Gnn: <коротко>` (и KDoc флага ссылается на тот же
   `Gnn`). Каждый пробел описан в таблице ниже. Новые пробелы дописывай в таблицу и в отчёт, не молчи о них.
5. **Отчёт.** В итоговом отчёте пользователю: список `Gnn` с тем, что сломано/отключено и что нужно от бэкенда (колонка «Нужно от бэкенда»).
6. В коде нет `@UnverifiedContract`-таблиц с догадками. Единственные клиентские допущения, не меняющие запросы: разбор вставленной ссылки из письма
   (G01) — пометка есть.

## Что определено и реализуется (кратко)

- **Авторизация:** `register` (201 `{status: pending}`, 403, 409, 503), `confirm` (204, 400/404, 409, 410, 403), `login` (200, 401, 403), `sessions/current` (GET/DELETE), `users/me/email`.
- **Профиль:** `GET /users/{id}/profile`, `GET/PUT /users/me/profile` (поля из `UserProfileInput`; `display_name` обязателен), `open_to_collaboration` — поле профиля (настройки = один тумблер через чтение-изменение-запись).
- **Достижения:** `GET /users/{id}/achievements`, `GET/POST /users/me/achievements`, `PUT/DELETE …/{id}` (`expected_revision`), `POST …/{id}/submit`; `kind` — `education | certificate | scientific | project`.
- **Отзывы:** `GET /users/{id}/reviews` (`limit`/`offset`, без `total`).
- **Поиск людей:** `q`, `university`, `skill[]`, `interest[]`, `my_university`, `open_only`, `verified_only`, `verified_projects`, `publications`, `limit`/`offset`; рекомендации людей (`limit`).
- **Проекты:** `GET /projects/{id}`, `GET /search/projects` (`q`, `field`, `tag[]`, `limit`/`offset`), `POST /projects/{id}/roles` (`title`, `slots`, `expected_revision`, `skills`, `description`).
