# Реестр пробелов API (правило «без догадок»)

Статус на 2026-10-19. Источник правды о бэкенде — `docs/openapi.yaml` (Gateway API **v2.5.0**; относительно v2.4.0 добавлен только административный API `/api/v1/admin/*` для сотрудников — модерация, аудит, пользователи, проекты; клиентскому приложению он не нужен. Все 43 публичных пути и все схемы клиента побайтно те же, поэтому пробелы ниже остались прежними). **Требование пользователя: API не угадывать.** Решение пользователя 2026-10-19: значения полей, которые сервер только хранит (тип проекта, сфера, срок, типы проектов профиля), задаёт клиент по дизайну и отправляет текстом (`scientific`, `recruiting`, `up_to_3_months`…) — таблица значений, формат дат и включённые флаги в `docs/api-values.md`; правило ниже остаётся для того, что сервер пишет или толкует сам.
Работаем только по тому, что в спецификации определено; всё, чего не хватает, помечается здесь и в коде, и приложение к этим местам
вернётся, когда бэкенд опишет API. Этот файл главнее документов архитекторов (`docs/gateway-block2-profiles.md`,
`docs/gateway-blocks3-5-search-and-projects.md`): везде, где они предлагают «лучшее предположение» (синонимы, значения enum, форматы дат,
значения `mine`/`action`/`type`), действует это правило, а не предложение.

## Правило

1. **Определено = можно использовать.** Определено то, что названо в схеме или описании: пути и методы, имена и типы полей, обязательные
   поля, границы (`limit` 1..100, `offset` 0..10000), enum параметра `kind` у достижений (`education | certificate | scientific | project`),
   `RegistrationResult.status = pending`, `EmailStatus.status = pending | verified`, коды ответов из таблицы ответов, смысл из `summary`/`description`
   (например, «Создать и сразу опубликовать проект», «Повтор с тем же email заменяет пароль и токен заявки»).
2. **Строка без перечня значений (`type: string` без `enum` и без описания значений) — пробел.** Мы НЕ придумываем её значения: ни в запросах,
   ни при разборе ответов (никаких синонимов, регистров, «наиболее вероятных» строк). Что делаем вместо этого:
   - **запрос:** параметр или поле с неопределёнными значениями не отправляем; если поле обязательно на сервере, а значения не известны, то
     операция в режиме Gateway **недоступна** (возможность выключена флагом, см. ниже), а не отправляется «на удачу»;
   - **ответ:** неопределённая строка читается как «неизвестно» (`null`) либо показывается как есть, если это свободный текст; интерфейс
     скрывает то, что без неё не построить (чип, баннер, действие);
   - **сохранение чужих данных:** при «прочитал — изменил — записал» (`PUT /users/me/profile`) значения неопределённых полей возвращаются на
     сервер как пришли.

2а. **Исключение 2026-10-19.** Для полей, которые сервер только хранит (тип проекта, сфера, срок, типы проектов профиля), значения задаёт клиент по дизайну и
   отправляет текстом (`scientific`, `up_to_3_months`, `publish`…); таблица значений, формат дат, правила для неизвестных значений и список включённых флагов — `docs/api-values.md`. Пункты 2–3
   («не отправляем», флаги возможностей) остаются для полей, которые сервер пишет или интерпретирует сам: статусы работ и документов (G12), `author_role` (G13),
   статус участника (G52), статусы откликов, смысл `mine` и `profile_user_id` (G44). Пробелы, закрытые так, помечены в таблице («Закрыт решением 2026-10-19»);
   включённые без подтверждения бэкенда — «Включён, не подтверждён бэкендом». Новые метки `API-GAP` для них не ставятся: в коде и KDoc ссылка на `docs/api-values.md`.

3. **Возможности (capabilities).** Каждый источник данных, у которого есть пробел, объявляет флаги возможностей (например,
   `ProjectsCapabilities.canCreate`). Флаг выключен в Gateway-источнике, пока пробел не закрыт (моков, которые играли бы более полный сервер, у
   подключённых фич больше нет: мок удаляется в том же шаге, где фича переходит на API). Интерфейс читает флаги и прячет или отключает затронутое
   действие с понятным текстом, а не показывает вымышленные данные. Если операцию всё же вызвали при выключенном флаге, источник бросает
   `FeatureUnavailableException(gap)` (`:common`) и запрос не отправляет. Закрытие пробела = смена значения флага + реализация вызова, больше ничего.
4. **Пометки.** Каждое место в коде, где пробел сказывается, помечено комментарием `API-GAP Gnn: <коротко>` (и KDoc флага ссылается на тот же
   `Gnn`). Каждый пробел описан в таблице ниже. Новые пробелы дописывай в таблицу и в отчёт, не молчи о них.
5. **Отчёт.** В итоговом отчёте пользователю: список `Gnn` с тем, что сломано/отключено и что нужно от бэкенда (колонка «Нужно от бэкенда»).
6. Клиентские допущения, не подтверждённые бэкендом, помечены в коде (`@UnverifiedContract` или KDoc «не подтверждено бэкендом»): разбор вставленной ссылки из
   письма (G01, `ConfirmationLinks`) и, с 2026-10-19, значения `action` перехода проекта (G42, `ProjectActions`), разбор статуса проекта (G41), формат дат `planned_*`
   (G43, `ProjectDates`) и способ получения «моих проектов» — обход `GET /projects` с фильтром по владельцу на клиенте (G44); подробности — `docs/api-values.md`.
   Таблиц значений, которые сервер пишет сам (статусы работ и документов и т. п.), в коде по-прежнему нет.

## Что определено и реализуется (кратко)

- **Авторизация:** `register` (201 `{status: pending}`, 403, 409, 503), `confirm` (204, 400/404, 409, 410, 403), `login` (200, 401, 403), `sessions/current` (GET/DELETE). `users/me/email` (`EmailStatus`) в спецификации есть, но приложение его не вызывает: не используется.
- **Профиль:** `GET /users/{id}/profile`, `GET/PUT /users/me/profile` (поля из `UserProfileInput`; `display_name` обязателен), `open_to_collaboration` — поле профиля (настройки = один тумблер через чтение-изменение-запись).
- **Достижения:** `GET /users/{id}/achievements`, `GET/POST /users/me/achievements`, `PUT/DELETE …/{id}` (`expected_revision`), `POST …/{id}/submit`; `kind` — `education | certificate | scientific | project`.
- **Отзывы:** `GET /users/{id}/reviews` (`limit`/`offset`, без `total`).
- **Поиск людей:** `GET /search/people`. Клиент описывает все определённые параметры (`q`, `university`, `skill[]`, `interest[]`, `my_university`, `open_only`,
  `verified_only`, `verified_projects`, `publications`, `limit`/`offset`), экран 08 отправляет `q`, `university`, `skill[]`, `verified_only`, `verified_projects`,
  `publications`, `project_type` (код типа, только когда выбран один; G11) и страницу (по 20; «Найдено N» — `total`, G34); `interest`, `my_university` и
  `open_only` в 08b не выведены. «Показать N» — тот же вызов с `limit=1`.
- **Рекомендации людей:** `GET /recommendations/people?limit=10` (G32, G33).
- **Проекты:** `GET /projects/{id}` (страница 04, экран 07), `GET /search/projects` (`q`, `field` названием сферы, `type` и `duration` текстом — только когда выбран один чип,
  `tag[]`, `limit`/`offset`; страницы по 20; `status`, `mine`, `profile_user_id` не отправляются: G41, G44; смысл `q`/`tag` и порядок — G53), `POST /projects`
  (создание: тип и сфера текстом, ISO-даты, роли с `slots = 1`; G40, G43, G46), `GET /projects` (только для «Я инициатор»: страницы по 100, до 10 страниц, фильтр по владельцу
  на клиенте; G44), `POST /projects/{id}/transitions` («Снять с публикации»: `action = "pause"`, `expected_revision`; G42), `POST /projects/{id}/roles` (`title`, `slots = 1`,
  `expected_revision`, `skills`; `description` не вводится; 409 → проект перечитывается, G48; новая роль по разнице id, G54). Значения — `docs/api-values.md`.
- **Не реализуется:** отклики, приглашения, участники — 2-й спринт (G51).
